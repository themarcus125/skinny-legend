# Skinny Legend v1.1 — Feature additions

**Date:** 2026-09-12  **Status:** Approved  **Extends:** `2026-09-11-skinny-legend-design.md`
**Linear:** SKI-47 (Momo link), SKI-45 (sign-in video), SKI-44 (group map), SKI-46 (i18n), SKI-48 (push reminders)

Build order: Momo → video → map → i18n → push. Push is blocked on a Firebase project + APNs key (SKI-40/42); everything up to the send call is built against a fake sender.

## A. Momo fund link (SKI-47, iOS only)

Account tab, settings card: a "Quỹ nhóm" row (SF Symbol `banknote`) above "Gửi góp ý" that opens `https://quy.momo.vn/v2/GZqk7REIhy?cover=f131` via SwiftUI `Link`. The URL is a constant `AppMode.momoFundURL` (per-challenge, no API change). Row is one combined accessibility element with hint "Mở trang quỹ Momo".

## B. Sign-in background video (SKI-45, iOS only)

- Asset: Pexels "Group Exercise Session on a Sunny Day" by Franco Garcia (video 38676016; Pexels licence: free, no attribution, modification allowed, app use permitted). Transcoded to vertical 1080×1920 H.264, ≤ 12 s, ≤ 8 MB, no audio track, bundled as `ios/SkinnyLegend/Resources/signin-bg.mp4`. The source URL and licence are recorded in `ios/SkinnyLegend/Resources/ATTRIBUTION.md`.
- `SignInView` renders `LoopingVideoBackground` (an `AVPlayerLayer` in a `UIViewRepresentable`, muted, looped via `AVPlayerLooper`, `resizeAspectFill`) beneath a vertical gradient from `.black.opacity(0.15)` to `.black.opacity(0.65)` so the title and buttons stay legible. The player pauses on `scenePhase != .active` and resumes on `.active`.
- Fallback to the existing `WarmBackground` when `accessibilityReduceMotion` is on, when the asset is missing, or when the player fails. `SignInBackground.mode(reduceMotion:assetAvailable:) -> .video | .gradient` is a pure function with unit tests.

## C. Group map (SKI-44, API + iOS + admin)

- **API** `GET /entries/map?days=30` (active users only; `days` 1–90, default 30; cap 500 pins, newest first): `{ pins: [{ entryId, lat, lng, placeName, takenAt, localDate, categories, thumbUrl, user: { id, displayName, avatarUrl } }] }`. Only confirmed entries with both coordinates. Tests: filters by window and status, excludes null coordinates, cap.
- **iOS** `MapScreen` pushed from a toolbar button on the Feed ("Bản đồ"). SwiftUI `Map` (MapKit) with one `Annotation` per pin drawing `AvatarView` in a 36 pt glass ring; pins within ~50 m are grouped client-side into one annotation with a count badge (pure `MapClusterer.cluster(pins, radiusMeters:)` with tests). Tapping a pin (or a cluster with one member) opens the existing entry card; tapping a multi-member cluster lists its entries. Initial camera fits all pins; empty state "Chưa có địa điểm nào được chia sẻ." `MapModel` loads via `APIClient.mapPins(days:)`; `MockAPIClient` derives pins from the seed's coordinates.
- **Admin** page "Bản đồ" (sidebar, after Mục ghi): `react-leaflet` + OpenStreetMap tiles (no API key), avatar markers, popup with thumbnail/member/date/categories, days filter (7/30/90). Read-only. Uses `AdminApi.mapPins(days)` against the same endpoint (admin token). Vitest for the marker mapping helper; visual check in mock mode with seeded pins.

## D. i18n — Vietnamese + English (SKI-46, API + admin + iOS)

- **Locale model:** `users.locale` enum `vi | en`, default `vi`; `PATCH /me { locale }`; included in the user DTO. First launch uses the device/browser locale; an explicit choice persists on the user.
- **API:** error `code`s are the contract; `message` stays Vietnamese as a fallback only. Vision prompt keeps Vietnamese reasons (AI output); the `reason` language follows the user's locale when known (`vi`/`en` instruction in the system prompt). Push copy (section E) is templated per locale.
- **iOS:** all 186 user-facing literals across 41 files move to `Localizable.xcstrings` (source language `vi`, `en` translations); `Category.label`, `APIError.userMessage`, cap/streak wording, relative dates (`LocalDay.display` via locale-aware formatters). Account gets a "Ngôn ngữ" picker: Hệ thống / Tiếng Việt / English, writing `locale` and applying `.environment(\.locale)` at the root. Tests keep asserting Vietnamese under a forced `vi` locale; a new `LocalizationLintTests` scans source for stray Vietnamese literals.
- **Admin:** `next-intl` with `messages/vi.json` and `messages/en.json` (86 strings); sidebar language switch; `useTranslations` in components; Vietnamese is the source of truth. A lint script fails on stray Vietnamese literals in `src/`.

## E. Push reminders (SKI-48, API + iOS + admin)

- **Provider:** FCM (HTTP v1) through the existing Firebase project; iOS registers an FCM token via the Firebase Messaging SDK. Permission is requested after the user's first confirmed entry, never at launch.
- **Data:** `device_tokens` (id, user_id, token unique, platform `ios`, locale, created_at, last_seen_at) via `POST /me/devices { token, platform, locale }` and `DELETE /me/devices/:token`; `notification_log` (id, user_id, kind, payload_json, sent_at).
- **Planner** (pure, `packages/shared/src/notifications/plan.ts`, unit-tested): inputs = each active user's last confirmed local date, leaderboard scores, the log, `today`. Rules: `inactive_1d`/`inactive_3d`/`inactive_7d` when the gap is exactly 1, 3, 7 days; `rank_nudge` for ranks 2–5 when the gap to the next rank is ≤ 15 points ("Còn {gap} điểm là vượt {name}" and, if not rank 2, "{gapToTop} điểm nữa để dẫn đầu"); never the same kind to the same user within 24 h; nothing for rank 1; nothing after the challenge end date.
- **Job:** `apps/api/src/jobs/notify.ts` runs daily 20:00 ICT (Railway cron `0 13 * * *` UTC), builds the plan, sends via a `PushSender` interface (`FcmSender` real, `FakeSender` in tests), logs every send. Templates per locale (vi/en).
- **iOS:** deep link from a tapped notification to the Track tab; a "Thông báo" toggle in Account that registers/unregisters the device.
- **Admin:** "Thông báo" page: log table (user, kind, sent_at) and a "Gửi thử" button that calls `POST /admin/notifications/test { userId }`.

## Out of scope
Widgets, live "near me" location, rank nudges for rank 1, Android push.
