# Web PWA member app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `apps/web` — an installable, Vietnamese-first React PWA at full parity with the iOS member app — on top of three new shared packages (`packages/shared/src/wire`, `packages/api-client`, `packages/ui`) that the admin dashboard adopts in the same breath, plus two additive API endpoints/enums.

**Architecture:** The wire contract stops being duplicated: the zod schemas and inferred DTO types that live inline in `apps/api/src/routes/*.ts` move to `packages/shared/src/wire/`, and both the API and a new framework-free `packages/api-client` import them from `@skinny/shared`. `packages/api-client` exposes one `createApiClient({ baseUrl, getToken })` covering every member and admin endpoint, one `ApiError`/`describeError` pair, and a deterministic in-memory mock client seeded like the iOS `MockSeed` — so `apps/web`, `apps/admin` and the Playwright suite all drive the same fixtures. `packages/ui` lifts the token layer (`tokens.css` / `type.css` extracted from `apps/admin/src/app/globals.css`) and eleven presentational components out of the two clients. `apps/web` is a Vite 6 + React 19 SPA: React Router 7 data routes, TanStack Query v5 persisted to IndexedDB, `use-intl` over `messages/{vi,en}.json` seeded from the iOS String Catalog, Firebase web auth + messaging, `vite-plugin-pwa` for the shell. Every piece of pure iOS logic the app needs (clustering, streak dots, verdict state machine, app-mode decision, locale reconciliation, push registrar) is ported with its iOS test cases mirrored one-for-one. The API gains only `GET /places/nearby` (a cached, rate-limited Nominatim proxy) and two enum values; iOS is not touched.

**Tech Stack:** TypeScript 5 (strict), pnpm 10.30.3 workspaces, Vite 6, React 19, React Router 7, TanStack Query v5 + `@tanstack/query-persist-client-core` + `idb-keyval`, Tailwind v4, `use-intl`, `vite-plugin-pwa` (Workbox `generateSW`), Firebase JS SDK 12 (auth + messaging), `exifr`, Leaflet 1.9 + `react-leaflet` 5, Recharts, `@fontsource/be-vietnam-pro`, Vitest 3/5 + React Testing Library, Playwright, Hono 4 + Drizzle + Postgres 16 + Zod 4 on the API side, Cloudflare Pages.

**Spec:** `docs/superpowers/specs/2026-09-14-web-pwa-design.md` (binding), on top of `docs/superpowers/specs/2026-09-11-skinny-legend-design.md` (rulebook, API shape, error envelope) and `docs/superpowers/specs/2026-09-12-v1.1-features-design.md` §D (locale) and §E (push).

## Global Constraints

- **Vietnamese is the source of truth.** Every user-facing string is a catalog key whose `vi` value is the Vietnamese copy and whose `en` value is a real translation. No Vietnamese literal ever lands in `src/` — `scripts/lint-i18n.mjs` (reused from the admin) fails the lint if one does.
- **Typeface: Be Vietnam Pro**, weights 400–800, via `@fontsource/be-vietnam-pro` (OFL). No other font is loaded.
- **`docs/design-system/tokens.md` is authoritative** for every colour, size, radius, and elevation — including the two documented light-mode accessibility deviations (`--success` `#3F5D43`, `--warning` `#6F5412`) and the `--fg-subtle`-is-decoration-only rule. Both clients ship the same values.
- **pnpm workspaces**, `packageManager: pnpm@10.30.3`, Node ≥ 22. New packages go under `packages/*`; new apps under `apps/*` (both globs already exist in `pnpm-workspace.yaml`).
- **TypeScript strict** in every package (`"strict": true`, no `any` in exported signatures).
- **ESLint 9 flat config, like the admin's** (`apps/admin/eslint.config.mjs`): one `eslint.config.mjs` per new package/app, `pnpm --filter <pkg> lint` runs it.
- **Commit prefixes**, one commit per task: `feat(shared)`, `feat(api)`, `feat(admin)`, `feat(web)`, `feat(ui)`.
- **Test floors — existing counts are a floor, never a ceiling.** At the time of writing: shared **56**, api **150**, admin **132**. Read the current number out of the runner before each task and require it not to drop. `packages/api-client`, `packages/ui` and `apps/web` set their own floors as they are created.
- **One API-suite runner at a time, one migrator at a time.** `apps/api`'s tests share a single Postgres database and `resetDb()` truncates it; never run two `pnpm --filter @skinny/api test` invocations concurrently, and never run `db:migrate` while a suite is running.
- **The admin dev server on `:3001` is the user's.** Never start, restart or kill it. `apps/web`'s dev server uses Vite's default `5173`.
- **iOS is untouched.** No file under `ios/` is created, edited or deleted by any task in this plan; `ios/` is read-only source material for the ports.

```js
#!/usr/bin/env node
// Builds messages/en.json from messages/vi.json by looking each Vietnamese value up in the iOS
// String Catalog (its keys ARE the Vietnamese source strings). Web-only strings the catalog has
// never seen live in messages/web-only.json, keyed by the same dotted path. Vietnamese stays the
// source of truth: this script never invents an English value.
import { readFileSync, writeFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';

const ROOT = fileURLToPath(new URL('..', import.meta.url));
const XCSTRINGS = fileURLToPath(new URL('../../../ios/SkinnyLegend/Localizable.xcstrings', import.meta.url));

const vi = JSON.parse(readFileSync(`${ROOT}messages/vi.json`, 'utf8'));
const webOnly = JSON.parse(readFileSync(`${ROOT}messages/web-only.json`, 'utf8'));
const catalog = JSON.parse(readFileSync(XCSTRINGS, 'utf8')).strings;

/** %@ / %lld / %1$@ → ICU {0}, {1}, … in source order, so use-intl can format them. */
function toIcu(text) {
  let index = 0;
  return text.replace(/%(\d+\$)?(@|lld|d|f)/g, (_m, position) =>
    `{${position ? Number(position.slice(0, -1)) - 1 : index++}}`);
}

const flat = (node, prefix = '') =>
  typeof node === 'string'
    ? [[prefix, node]]
    : Object.entries(node).flatMap(([k, v]) => flat(v, prefix ? `${prefix}.${k}` : k));

const missing = [];
const en = {};
for (const [path, viValue] of flat(vi)) {
  const fromIos = catalog[viValue]?.localizations?.en?.stringUnit?.value;
  const value = webOnly[path] ?? (fromIos && toIcu(fromIos));
  if (!value) { missing.push(`${path}: ${viValue}`); continue; }
  path.split('.').reduce((node, key, i, keys) =>
    i === keys.length - 1 ? (node[key] = value) : (node[key] ??= {}), en);
}
if (missing.length > 0) {
  console.error(`seed-messages: ${missing.length} key(s) with no translation.\n` +
    `Add them to messages/web-only.json:\n${missing.join('\n')}`);
  process.exit(1);
}
writeFileSync(`${ROOT}messages/en.json`, `${JSON.stringify(en, null, 2)}\n`);
console.log(`seed-messages: wrote ${flat(vi).length} keys to messages/en.json`);
```

English gets (`{0}`, `{1}`), so both sides format identically.

// apps/web/src/lib/locale-reconcile.ts
export function reconcileLocale(i: LocaleReconcileInput): LocaleReconcileResult {
  // An explicit local choice is this device's source of truth: push it when the server disagrees.
  if (i.choice !== 'system') {
    const push = i.userStatus !== 'disabled' && i.serverLocale !== i.choice ? i.choice : null;
    return { store: i.choice, push };
  }
  // A fresh install has never told the server anything: send what the device resolves to, keep "system".
  if (i.isFreshInstall) {
    const resolved = resolveLocale('system', i.deviceLanguage);
    return { store: 'system', push: i.userStatus !== 'disabled' ? resolved : null };
  }
  // Otherwise "system" adopts whatever explicit value the server already holds (the console, or another client).
  return { store: i.serverLocale, push: null };
}

export function isAlreadyTracked(s: VerdictState): boolean {
  // POST /entries confirms straight from the verdict, so a successful verdict means the entry
  // already counted. A failed verdict leaves it pending, so both halves are checked.
  return s.mode.kind === 'created' && s.entry.status === 'confirmed' && !s.mode.verdict.failed;
}
export function needsSave(s: VerdictState): boolean { return !isAlreadyTracked(s) || hasChanges(s); }
export function canSave(s: VerdictState): boolean {
  // PATCH requires ≥ 1 category, and a scored entry must never be corrected down to zero.
  return !s.isSaving && !(needsSave(s) && s.selected.length === 0);
}
export function outcome(s: VerdictState): VerdictOutcome {
  if (isAlreadyTracked(s)) return 'tracked';
  return s.confirmedEntry ? 'confirmedByHand' : 'abandoned';
}

- [ ] **Step 3: Write the clusterer**

```ts
export function clusterPins(pins: MapPinDto[], radiusMeters: number): MapCluster[] {
  const clusters: MapCluster[] = [];
  for (const pin of pins) {
    const point = { lat: pin.lat, lng: pin.lng };
    const index = clusters.findIndex((c) => distanceMeters(c.center, point) <= radiusMeters);
    if (index === -1) { clusters.push({ id: pin.entryId, center: point, pins: [pin] }); continue; }
    const cluster = clusters[index]!;
    cluster.pins.push(pin);
    cluster.center = {
      lat: cluster.pins.reduce((sum, p) => sum + p.lat, 0) / cluster.pins.length,
      lng: cluster.pins.reduce((sum, p) => sum + p.lng, 0) / cluster.pins.length,
    };
  }
  return clusters;
}
```
`distanceMeters` is the haversine formula with `R = 6_371_000`, identical to the API's
`haversineMeters` (Task 4) — the two live in different packages because the client must not import
server code, and both are covered by the ~111 m assertion.
